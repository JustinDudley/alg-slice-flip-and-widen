

THERE EXIST AT LEAST 2 BRANCHES OF THIS PROJECT IN git



Copy a list of algs from StickerSolve into the file "alg_list_input.txt"
  - The program is built to handle StickerSolve algs with the following qualities:
      - they have face turns only
      - They do not rotate the core (since I didn't know StickerSolve could do that!)
      - They swap either two edge pieces or two corner pieces, and they belong to 1 of the 6 DO6 groups as far as their treatment of centers
Run the program
Look at the output file for a list of newly generated algs




The program will take this list of StickerSolve algs
It will determine which of the six DO6 groups the alg belongs to
It will substitute in slices, for instance replacing F' B with S 
It then puts the alg into Alg--YorZ--X format.
  - It does this by looking at the resultant trailing whole-cube-rotations, those it walked in with plus those generated by slice substitution
  - It uses this information to put the alg into one of 24 categories (or 28, depending on how you count it)
       - btw the number 24 corresponds to the number of ways a cube can be rotated with whole-cube-rotations
  - Alg--YorZ--X format is:   Sequence of turns without whole cube rotations -- a single Y or Z component (ex. Z2) -- a single X-component (ex. X')
       - U2 F' L2 U2 F' R' L' (y2) U F2 R2 U L' R' B' L R (x),  put into Alg--YorZ--X notation, is:
       - U2 F' L2 U2 F' R' L' U B2 L2 U R' L' F' R L (y2) (x)
       - (this is a poor example)
       - I figured out that, amazingly enough, ANY alg in the world can put into this format (and induces an identical pattern on the cube)

It then ripples the Y or Z component from the right of the alg to the left, one turn at a time 
For each ripple-round, it analyzes all possible ways to convert R and L turns into their complement r and l (and r', l2, etc.) turns
  - It uses the itertools package to do this. IF THE PROGRAM HAS A HEART, THIS IS IT
Also for each ripple-round, it looks at each alg and inserts an additional alg with a lowercase udfb if appropriate
  - These algs are mostly undesirable, but it's nice to know about them. They end up constituting maybe 10% of the total generated algs.
  - for instance,    S D' U' r F B D' l2 B2 D' R L F D2 l2 Z B R2     becomes    S D' U' r F B D' l2 B2 D' R L F D2 l2 f R2




It prints results to an output file.
The output algs may contain leading Ys or Zs, trailing Ys or Zs, OR INTERNAL Ys or Zs   (these are whole-cube-rotations)
It is currently designed not to procuce any Xs as whole-cube-rotations
Typically, a list of 10 input algs will generate about 3,000 output algs




Any alg can be endlessly manipulated by adding more and more whole-cube-rotations at the front, the end, or internally.
This program takes StickerSolve algs and aims to produce every conceivable alg that can be generated, within certain parameters:
  - No more than ONE whole-cube-rotation (and it's always a Y or Z, never an X because X-axis turns are handled with lowercase r and l)
  - No more than one lowercase letter such as udfb.  (There are lots of r, l)
The program produces many undesirable turns such as H and B2.  These can be weeded out later with various filtering techniques
